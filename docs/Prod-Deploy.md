# Прод v2: выкат и откат

Прод: **https://vlist-v02-prod.smileme.ai**, конфиг `wrangler.prod.jsonc`, воркер `vlist-v02-prod`.

## Команды

```
npm run deploy:prod      # выкатить текущий коммит
npm run versions:prod    # что было на проде, от старого к новому
npm run rollback:prod    # вернуть версию, которая была до текущей
npm run rollback:prod -- <version-id>   # вернуть конкретную версию
```

`deploy:prod` перед выкатом отказывается работать на грязном дереве (`--allow-dirty` снимает
запрет), прогоняет юнит-тесты (`--skip-tests` снимает), собирает клиент, затем **загружает
версию** и **переводит на неё трафик** — два отдельных шага.

Разделение и есть весь смысл конструкции. Загруженная версия остаётся на стороне Cloudflare
со своим идентификатором и меткой коммита, из которого собрана, поэтому возврат к вчерашней
сборке — активация уже существующего идентификатора: без пересборки, без переключения веток
и даже если репозиторий уехал вперёд.

## Почему отдельный воркер

`wrangler.jsonc` — это v1 (`vlist-cloudflare-backend`), и его деплоит другой агент. Общий
конфиг означал бы гонку, в которой каждая сторона может опубликовать поверх другой. Поэтому
у прода v2 свой файл конфигурации, своё имя воркера, свой домен и свой Durable Object.
Пересечений по ресурсам нет ни одного: деплой v1 не может задеть v2, и наоборот.

Имя конфига в скриптах зашито и не является параметром. Флаг, которым эти скрипты можно
направить на чужого воркера, — единственная ошибка, которую нельзя откатить.

## Данные

Durable Object принадлежит воркеру, а не версии, поэтому выкат и откат кода данных не
касаются. Проверено на живом проде: создана задача, выкачена новая версия, задача на месте;
сделан откат на предыдущую версию, задача на месте.

Уничтожить данные могли бы две вещи, и обеих в `wrangler.prod.jsonc` намеренно нет:

- привязки `TEST_RESET_TOKEN` — она открывает `POST /reset`, который пересоздаёт документ;
- переименования класса DO (`ListDocumentDO`) или метки миграции — после него воркеру
  достался бы другой, пустой объект, а старый остался бы недостижимым.

Чего откат **не** делает: он возвращает код, но не данные. Если версия успела изменить
форму хранения, возврат кода оставит данные в новой форме. Такие изменения выкатывайте
отдельно от прочих, чтобы откат оставался безопасным.

## Что нужно сделать один раз

Ключ OpenAI на проде не настроен — секретов у воркера нет вообще. Без него голосовые ручки
отвечают `MODEL_UNAVAILABLE`, остальное приложение работает. Два способа:

- в интерфейсе: настройки → ключ OpenAI (разовая установка открыта, пока ключа нет);
- с машины, где есть wrangler: `wrangler secret put OPENAI_API_KEY --config wrangler.prod.jsonc`.

## Доступ

Прод открыт так же, как дев: аутентификации нет. Любой, кто знает адрес, может открыть
платную GPT-Live сессию на настроенном ключе, прочитать расшифровки на `/live-log` и
изменить список задач. Это осознанное решение; если оно изменится, гейт ставится в
`worker/v2/index.js` перед разбором маршрутов.

## Пересоздание воркера с нуля

`versions upload` не создаёт воркера и не привязывает домен, поэтому самый первый выкат
делается обычным деплоем, а дальше работают скрипты:

```
npm run build:v2 && npx wrangler deploy --config wrangler.prod.jsonc
```
