# Делегирование задачи Грок-боту

Код: `worker/v2/grok.js` (хранение, вызов вебхука, приём ответа, чтение треда, глубокая ссылка),
`worker/v2/grok-pages.js` (страницы), маршруты — `worker/v2/index.js`,
интерфейс — `src/v2/client/client.js`. Инструкция рутины для бота — `docs/Grok-Bot-Routine.md`.

Грок не меняет дерево. Единственное исключение — `done: true` в ответе: задача переходит в Done
обычной командой графа `setStatus` с `source: "grok"`, попадает в журнал и откатывается как любое
действие.

## Секреты Worker'а

| Секрет | Что это |
|---|---|
| `GROK_WEBHOOK_URL` | Адрес «POST to» из вебхука рутины |
| `GROK_WEBHOOK_KEY` | Ключ вебхука. Обычный ключ уходит как `Authorization: Bearer <key>`; ключ с префиксом `whsec_` — подпись Standard Webhooks (`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64 HMAC-SHA256 от {id}.{timestamp}.{body}>`) |
| `GROK_REPLY_TOKEN` | Токен бота: ответы, чтение треда, публикация страниц |

Переменные (не секреты): `GROK_BOT_ID` — id бота для глубокой ссылки, пусто — основной бот;
`GROK_PAGES_HOST` — домен страниц. Биндинг R2 `GROK_PAGES` — бакет страниц. Настройка — в
`docs/Prod-Deploy.md`.

Нет любого из трёх — карточка показывает «Грок не подключён», кнопка неактивна, `/api/grok/delegate`
отвечает `503`.

## Хранение

Таблица в SQLite Durable Object, не в снимке документа:

```
grok_messages(
  id TEXT PRIMARY KEY,   -- id сообщения; для ответов Грока = replyId
  task_id TEXT NOT NULL,
  role TEXT NOT NULL,    -- user | grok | system
  text TEXT NOT NULL,
  at TEXT NOT NULL,      -- ISO
  reply_to TEXT,         -- grok: id сообщения пользователя; system: id упавшего сообщения
  run_uuid TEXT,         -- runUuid из ответа вебхука
  state TEXT             -- user: sending | accepted | failed
)
```

Тред задачи — все строки с её `task_id` по `at`. Удаление и архивирование задачи тред не трогают.

## POST /api/grok/delegate

Тело от страницы: `{ "taskId": "...", "messageId": "<uuid>", "text": "..." }`, `text` до 8000
символов.

| Ответ | Когда |
|---|---|
| `200 {"message": {...}, "webhook": {"status": N}}` | Сообщение записано; `message.state` — `accepted` или `failed` |
| `200 {"message": {...}, "duplicate": true}` | Тот же `messageId` уже отправляется или принят: второй строки нет, бот не будится |
| `400` | Пустой текст, длиннее 8000, нет `taskId`/`messageId`, `messageId` занят другой задачей |
| `404` | Нет такой задачи |
| `503` | Грок не подключён |

Сообщение в `failed` отправляется заново тем же `messageId` — это кнопка «Повторить»; его `at`
становится временем повтора. Сообщение, оставшееся в `sending` дольше 30 с (вызов потерян вместе с
перезапуском объекта), считается упавшим: его тоже можно повторить. Автоповторов нет.

Тело вызова вебхука:

```json
{
  "kind": "voicelist.delegation",
  "taskId": "t42",
  "message": { "id": "m-uuid", "text": "Найди три варианта …", "at": "2026-11-24T10:00:00Z" },
  "task": { "title": "Купить кондиционер", "status": "Open", "deadline": null,
            "path": ["Дом", "Спальня"], "children": [{ "title": "Замерить комнату", "status": "Done" }] },
  "thread": [ { "id": "m-prev", "role": "user", "text": "…", "at": "…" } ],
  "reply": { "url": "https://<хост запроса>/api/grok/reply" }
}
```

`thread` — прежние сообщения без текущего и без `system`, последние 30. `children` — подзадачи без
архивных. `reply.url` строится из хоста запроса: дев и прод отвечают каждый себе.

Ответ вебхука подтверждает только запуск рутины. Таймаут 15 с.

| Ответ вебхука | Состояние | Системное сообщение в треде |
|---|---|---|
| `200 {"success":true,"runUuid":"…"}` | `accepted`, `run_uuid` записан | — |
| `401` | `failed` | Ключ вебхука неверный или перевыпущен |
| `400` | `failed` | Рутина Грока выключена или упёрлась в лимит запусков |
| `404` | `failed` | Вебхук Грока больше не существует |
| `5xx`, сеть, таймаут, иное | `failed` | Грок не ответил на вызов |

## POST /api/grok/reply

Заголовок `Authorization: Bearer <GROK_REPLY_TOKEN>`, сравнение за постоянное время. Origin у бота
нет, проверка Origin его не задевает. Тело до 32 КБ:

```json
{ "taskId": "t42", "replyTo": "m-uuid", "replyId": "r-uuid", "text": "Нашёл три варианта: …", "done": false }
```

`taskId`, `replyId`, `text` обязательны; `text` до 8000 символов; `replyTo` и `done` необязательны:
без `replyTo` бот пишет в тред по разговору в своём приложении, без вызова вебхука.
`replyTo`, если задан, должен быть сообщением пользователя из треда этой же задачи. Ответ на сообщение,
которое медленный вебхук пометил `failed`, переводит его в `accepted`: вызов дошёл, «Повторить»
больше не предлагается.

| Ответ | Когда |
|---|---|
| `200 {"stored":true}` | Записана строка `role=grok`, открытые вкладки получили обновление |
| `200 {"stored":true,"duplicate":true}` | `replyId` уже записан: второй строки нет; `done` повторно применяется, только если первое закрытие не случилось |
| `401` | Токен неверный или не задан |
| `400` | Тело некорректно или больше 32 КБ; `replyTo` не из треда задачи; `replyId` занят другой задачей |
| `404` | Нет такой задачи |

`done: true` на задаче не в Done и не в Archive → `setStatus Done`, `source: "grok"`, ключ журнала
`grok:<replyId>`. Задача уже Done или Archive — статус не трогается. Ключ журнала делает повтор
безопасным: закрытие, которое уже случилось или было откачено, не повторяется.

Треды и список страниц переезжают вместе с документом при `/api/v2/relocate`; тела страниц
остаются в общем бакете R2.

## GET /api/grok/thread?taskId=…

`Authorization: Bearer GROK_REPLY_TOKEN`. Отдаёт то же, что уходит в вебхук, без `message` и
`kind`: `{ taskId, task, thread, reply }`. Нужен боту, когда разговор продолжают в его
приложении по кнопке «Открыть в Гроке». `401` — токен, `404` — нет задачи, `400` — нет `taskId`.

## Страницы

Бот публикует самодостаточную HTML-страницу и кладёт ссылку в свой ответ. Тело — в R2
(`GROK_PAGES`, ключ `pages/<id>.html`), метаданные — в SQLite объекта:

```
grok_pages(id TEXT PRIMARY KEY, task_id TEXT, title TEXT NOT NULL, size INTEGER NOT NULL,
           created_at TEXT NOT NULL, updated_at TEXT NOT NULL)
```

API на домене приложения, `Authorization: Bearer GROK_REPLY_TOKEN` (токен проверяется до чтения
тела):

| Запрос | Ответ |
|---|---|
| `POST /api/grok/pages?taskId=…&title=…`, тело — сырой HTML до 10 МБ | `201 { id, url }` |
| `PUT /api/grok/pages/<id>` | `200 { id, url }` — содержимое заменено, ссылка та же |
| `DELETE /api/grok/pages/<id>` | `204` |

`401` — токен, `404` — нет задачи или страницы, `413` — больше 10 МБ, `503` — нет бакета или
домена страниц. `taskId` необязателен, `title` — до 200 символов, пусто — «Страница». `id` —
128 случайных бит в base64url (22 символа). Публикация, замена и удаление пишутся в лог
(`grok.page.*`: id, задача, размер, sha256 тела).

Отдача — только на домене страниц (`GROK_PAGES_HOST`: `vlist-pages.smileme.ai` на проде,
`vlist-pages-dev.smileme.ai` на деве). Тот же Worker различает домен по `Host`: там отвечает
только `GET /p/<id>`, всё остальное — `404`; на домене приложения `/p/<id>` — `404`. Заголовки:
`Content-Type: text/html; charset=utf-8`,
`Content-Security-Policy: sandbox allow-scripts allow-popups allow-forms allow-modals` (без
`allow-same-origin`), `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`,
`Cache-Control: no-store`. Ссылка — единственный доступ к странице.

## Глубокая ссылка «Открыть в Гроке»

`grokbot://app/v1/prompt?id=<GROK_BOT_ID>&text=<urlencode(текст)>`, без `id` при пустом
`GROK_BOT_ID`. Текст — `VoiceList, задача <taskId> «<title>». `; закодированный — до 1000
символов, длинное название обрезается с «…». По этой фразе профиль бота узнаёт задачу и читает
тред через `/api/grok/thread`. Ссылка работает только при установленном и залогиненном
приложении Grok Bot; текст лишь подставляется в поле, отправляет пользователь. Без секретов
кнопка неактивна.

## Интерфейс

- Карточка задачи, под подзадачами — блок «Грок»: тред с временем, системные строки мелким серым,
  текст Грока — plain text с переносами и кликабельными ссылками, без HTML. Под принятым сообщением
  без ответа — «Грок работает…»; у упавшего — «Повторить». Под тредом — страницы задачи
  (заголовок, время, ссылка в новой вкладке). Поле, кнопки «Открыть в Гроке» и «Делегировать
  Гроку»: пустой текст не уходит, во время отправки кнопка неактивна.
- Фронтир, под задачей с непустым тредом: последнее сообщение Грока (две строки) и время; если
  последнее слово за пользователем — «Грок работает…»; если вызов упал — текст ошибки. Тап открывает
  карточку на блоке «Грок».
- Обновления — тем же каналом, что и документ: сокет присылает `changed`, страница забирает
  `/api/v2/updates`; у тредов свой признак `grok` в ответе, и его сдвиг перечитывает документ.
  Поллинга нет.

## Лог

Оба запроса пишутся в лог событий объекта (`/api/live/log`, сессия `grok:<taskId>`):
`grok.delegate` — исходящее тело, код и тело ответа вебхука, `runUuid`; `grok.reply` — сырое тело
ответа бота и код, которым мы ответили. Ключи и токен в лог не попадают. Ответы с неверным токеном
не пишутся.
