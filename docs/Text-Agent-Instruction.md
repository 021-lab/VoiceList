# Инструкция текстовой модели

Текстовая модель (`AGENT_MODEL`, на проде `gpt-6-luna`, без рассуждений) получает реплику и
отвечает вызовами инструментов. Инструкция — `AGENT_RULES` в `worker/v2/model.js`:

1. Задача модели — определить намерение, вызвать инструменты, которые его выполняют, и вызовом
   `notDone(parts)` назвать части реплики, которые не стали вызовами.
2. Правила — шаблоны вида `(добавь|новая задача) X → addChild("inbox", X)`, сгруппированные по
   действию: создание, переименование, статус, срок, перенос, выбор цели.
3. Формальная JSON-схема всех инструментов. Она собирается из тех же описаний, что у голосовых
   моделей (`LIVE_TOOLS`), поэтому разойтись с ними не может.

`notDone` есть только у текстовой модели: без рассуждений модель не пишет текст рядом с
вызовами, и невыполненное может прийти только вызовом. Список задач он не меняет, его части
попадают в ответ строкой «Не выполнено: …».

## Корпус и проверка

Корпус — `docs/text-agent-corpus.json`: список задач, сегодняшняя дата и реплики с ожидаемыми
вызовами. Прогон на настоящей модели (нужен `OPENAI_API_KEY`):

    node scripts/eval-text-agent.mjs [модель]

Скрипт печатает расхождения и итог. 2026-10-20 на `gpt-6-luna` три прогона дали 45, 44 и 43
из 45 при медиане 1,3–1,5 с. Ошибки плавающие: иногда модель молча выбирает одну из двух
одноимённых задач или пропускает `notDone`.

Новая ошибка из журнала — сначала строкой в корпус, потом правка правил, потом прогон.
