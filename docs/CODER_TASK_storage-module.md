# Задание кодеру: storage-модуль — интеграция с бэкендом taosmd (v1)

Это точка входа ветки `taosmd-backend`. Перед началом прочитать [INTEGRATION_taosmd.md](./INTEGRATION_taosmd.md) (архитектура доступа) и канон бэкенда: https://github.com/021-lab/TaOS/tree/feat/user-statuses/docs/specs (`00-INDEX-focus-harness.md` → контракт API §4 Tasks, §5 A2A; TASK_LIFECYCLE §1 про пару рёбер).

## Архитектура (решение владельца, не пересматривать)

```
Приложение → storage-модуль → localStorage
                     └→ (Worker-proxy /api) → taosmd /tasks  [write-through]
                     └→ (Worker-proxy /api) → taosmd /a2a   [журнал действий]
```

- **Единственная точка доступа к состоянию**: приложение больше не трогает localStorage напрямую — только через storage-модуль.
- **Bootstrap**: если localStorage пуст — список задач загружается из taosmd (`GET /api/tasks` + `GET /api/tasks/edges`) и разворачивается в локальное дерево.
- **Write-through**: каждая операция приложения сразу меняет localStorage (UI не ждёт) и сразу же синкается в taosmd `/tasks`.
- **Журнал действий** параллельно уходит в A2A-канал лога (`thread=voicelist-log`, `from=user`) — одна запись журнала = одно сообщение `{id, ts, op, payload}`.
- **`list-data.js` удаляется полностью**: seed-снапшота больше нет, единственный источник начальных данных — taosmd. Убрать файл, ссылки на него в шаблоне/сборке/тестах/README и упоминания в инструкциях для форков. Пустой бэкенд + пустой localStorage = пустой список (не ошибка).
- Модуль живёт в исходниках `src/` и собирается в единственный self-contained `list-manager.html` (`npm run prepare-preview`). Внешних зависимостей не добавлять.

## API-контракт модуля (внутренний)

Приложение видит только этот интерфейс (имена — на усмотрение, семантика обязательна):
- `init()` — поднять состояние: localStorage либо bootstrap из taosmd.
- `getState()` — текущее дерево задач для рендера.
- `apply(op)` — единственная мутация: применить локально → записать localStorage → поставить в очередь синка (tasks + журнал).
- `syncStatus()` — `{online, queued, lastError, lastSyncTs}` для индикатора в UI.

## Маппинг в taosmd

| Операция приложения | Запрос |
|---|---|
| Создать задачу верхнего уровня | `POST /api/tasks {title, body?, priority?}` |
| Создать подзадачу | `POST /api/tasks` + **пара рёбер**: `parent` ребёнок→родитель и `blocks` ребёнок→родитель (единый хелпер, не разделять) |
| Переименовать / изменить текст | `POST /api/tasks/{id} {title?/body?}` |
| Смена статуса | `POST /api/tasks/{id} {status}` по таблице ниже |
| Перемещение в дереве (drag) | снять старую пару рёбер (`/edges/remove`) + создать новую |
| Удаление | удаления в taosmd нет — закрытие статусом |

Статусы: `Open → open`, `Done → closed`, `Focus → focus`, `Pause → pause`, `Archive → ` **TO-DECIDE** (у бэкенда нет отдельного archive: либо `closed` с потерей различия, либо `superseded`, либо амендмент enum в TaOS — решение владельца, до него не кодить этот случай).

Обратное чтение при bootstrap: `open/focus/pause` → одноимённые локальные; `closed/superseded` → `Done`; `in_progress`/`blocked` (поставлены агентами) → показывать как `Open` с пометкой, не перезаписывать их автоматически.

## Идентификаторы

- Канонический id задачи — id из taosmd. При создании офлайн выдаётся временный локальный id с явной пометкой; после успешного `POST /tasks` он заменяется серверным во всём локальном состоянии и в очереди (операции над ещё не созданной задачей ждут её id).
- Порядок очереди строгий (FIFO): создание родителя раньше рёбер, рёбра раньше мутаций ребёнка.

## Офлайн и ошибки

- Сеть недоступна — приложение работает полностью на localStorage, очередь копится и догоняет позже (экспоненциальный бэкофф, порядок сохраняется, не слать N+1 до подтверждения N).
- Очередь переживает перезагрузку вкладки (хранится рядом с состоянием).
- 4xx от сервера (невалидный статус, несуществующий id) — не ретрайть бесконечно: отложить в dead-letter и показать в индикаторе.
- При внешних изменениях в taosmd (агенты) v1 их не подхватывает автоматически; полная перезагрузка из бэкенда — явной кнопкой «Refresh from backend» (очищает локал и делает bootstrap; требует пустой очереди).

## Правила

- Провенанс: все мутации фронта — `created_by=user`; журнальные сообщения — `from=user`. Серверные дефолты не использовать (способ передачи `created_by` — TO-VERIFY №9 контракта; если сервер не принимает — добавляет Worker-proxy).
- Адрес API — относительный `/api/*`; базовый URL конфигурируем для локальной разработки, домены не хардкодить.
- Токен taosmd в браузер не попадает никогда.
- Прямой доступ к SQLite/файлам taosmd запрещён — только HTTP-контракт.

## Приёмка

1. Свежий браузер (пустой localStorage) + непустой taosmd → дерево задач построено корректно (иерархия из `parent`-рёбер, статусы по таблице).
2. Любая операция в UI → сразу видна в `GET /api/tasks` (и в `/api/tasks/edges` для структурных); создание подзадачи создаёт **оба** ребра.
3. Офлайн-серия операций → после восстановления сети состояние в taosmd идентично локальному; перезагрузка вкладки в середине очереди не теряет и не дублирует операций.
4. Журнал: все операции видны в `GET /api/a2a/messages?thread=voicelist-log` с `from=user`, порядок совпадает с UI-журналом.
5. `list-data.js` отсутствует в репо; сборка, тесты и доки не ссылаются на него.
6. `npm run test:unit` и `npm run test:e2e` зелёные (добавлены тесты на bootstrap, очередь, замену временных id, маппинг статусов); приложение остаётся self-contained одним файлом.

## Вне скоупа v1

Двусторонний синк с подхватом изменений от агентов, спека фронтир-резолвера, гейты APPROVE/ACCEPT, назначение агентов, голосовой ввод через бэкенд — всё это v2.
