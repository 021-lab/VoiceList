# Интеграция Gemini Live (прямое соединение из браузера)

Статус: реализовано и развёрнуто на дев-окружении. Это **второй** голосовой путь,
рядом с [GPT-Live](GPT-Live-Responses-Integration.md), а не замена ему: в интерфейсе
две кнопки, обе ведут в один и тот же документ и один и тот же журнал.

Причина существования второго пути — цена и задержка. Голосовой слой GPT-Live стоит
пять центов за минуту и обязан звать бэкенд-модель ради любого изменения. Gemini Live
держит инструменты сам и стоит около 2.3 цента за минуту, поэтому путь до изменения
короче на целую модель.

## Топология

```
браузер ──WebSocket: аудио + кадры──► Gemini Live (Google)
   │                                        │
   │  POST /api/live/gemini/session         │ toolCall
   ├────────────► Worker ── токен ──────────┘
   │                 (ключ, промпт, снимок задач — в токене)
   │
   ├─ POST /api/live/gemini/tools  ─► документ-DO: исполняет и отвечает
   └─ POST /api/live/gemini/frames ─► документ-DO: пишет в тот же лог
```

Главное отличие от GPT-Live: **sideband-соединения нет**. Браузер сам держит сокет с
Google, а вызовы инструментов и кадры для лога отправляет на сервер обычными POST.
Браузер здесь — ретранслятор, а не решающая сторона: аргументы вызова исполняет
Durable Object, он же возвращает результат, который браузер обязан отправить обратно
как `toolResponse`.

## Принятые решения

| Предмет | Решение |
| --- | --- |
| Модель | `gemini-3.8-live`, правится в настройках |
| Транспорт | WebSocket браузер ↔ Google напрямую |
| Доступ | Эфемерный токен: одноразовый, сессия 30 минут, старт в пределах 2 минут |
| Где лежит конфигурация сессии | Внутри токена, поле `bidiGenerateContentSetup` |
| Ключ Gemini | Проверяется у Google перед сохранением; заменяем; секрет воркера имеет приоритет |
| Инструменты | Объявлены в `setup.tools`, держит их сама голосовая модель |
| Состав инструментов | Те же изменения дерева, что у GPT-Live, **кроме правки промптов** |
| Поведение инструментов | Изменения `BLOCKING`, чтение фронтира `NON_BLOCKING` |
| Исполнение | Документ-DO, тем же путём команд, `source: gemini-live` |
| Ключ идемпотентности | Идентификатор вызова от модели, `seq: 1` |
| Повторный вызов | Одинаковое изменение в течение 30 секунд отвечается прежним результатом |
| Голос и язык | `Zephyr`, `ru-RU` на вход и на выход |
| Распознавание | Список языков из одного `ru-RU` — блок на все остальные |
| Границы реплики | Своя настройка детектора: чувствительный старт, терпеливый конец |
| Аудио в браузере | Вендорнутый слой Google `live-api-web-console`, Apache-2.0 |
| Снимок дерева | Плоская таблица, тот же формат, что у GPT-Live |
| Промпт | Свой, редактируется в настройках; снимок приписывает система |
| Реплики | Каждый ход, свой и пользователя, попадает в шину записью `kind: speech` |
| Связь изменения с репликой | `corrects` на реплику, из которой изменение выросло |
| Границы хода | Отмечает страница: у сервера нет аудио и нет признака конца реплики |
| Лог | Тот же `live_events`, события с префиксом `gm.` |
| Что пишется в лог | Транскрипты, вызовы и результаты, ошибки, `goAway`; аудио вырезается |

## Чем этот путь отличается от GPT-Live по существу

**Инструменты у голосового слоя есть.** У GPT-Live их нет по устройству, поэтому ему
выдаётся блок `<capabilities>` со списком того, что можно попросить у бэкенда. Gemini
этот блок не получает: он противоречит объявленным инструментам, и модель, прочитав
«своих инструментов у тебя нет», начинала пересказывать просьбы вместо их исполнения.

**Бэкенд-модели в этом пути нет.** Разбор речи, выбор инструмента и аргументы —
всё делает голосовая модель. Настройки бэкенд-модели и глубины её рассуждений к
этой кнопке не относятся.

**Правка промптов голосом недоступна.** Четыре инструмента чтения и записи промптов
в набор не включены сознательно: названия задач — недоверенные данные, лежат в
снимке, а запись в промпт переживает сессию. В пути GPT-Live цена этого риска
принята ради возможности; здесь она не принималась.

**Разговор попадает в журнал задач, а не только в лог сессии.** Реплика пользователя
ложится в шину отдельной записью, изменение ссылается на неё, ответ модели — тоже. На экране
журнала это одно действие: фраза, что из неё вышло и что ответила модель. Кадры с
транскриптом страница присылает вместе с вызовом инструмента одним запросом, иначе изменение
опередило бы фразу и ссылаться было бы не на что.

**Снимок дерева не обновляется по ходу разговора.** Механизма дельт, аналогичного
`session.instructions.append`, у этого транспорта нет, а конфигурация запечатана в
одноразовом токене. Задача, созданная в середине сессии, видна модели только через
`getFrontier` или по её собственной памяти о вызове. Это известное ограничение, а не
недосмотр: обновление снимка потребовало бы пересоздания сессии.

**Продолжения сессии нет.** По `goAway` пользователю показывается «сессия истекает,
начните заново». Возобновление сессии (session resumption) не реализовано.

## Ключ

Ключ проверяется у Google дешёвым чтением (`GET /v1beta/models?pageSize=1`) **до**
сохранения. Это прямое следствие опыта с ключом OpenAI: там однократная установка
израсходована на непроверенное значение, и заменить его через приложение уже нельзя.
Здесь «настроен» означает «Google его принимает», а переставший работать ключ
заменяется без сброса документа.

## Маршруты

| Маршрут | Назначение |
| --- | --- |
| GET /api/live/gemini/key/status | Проверен ли ключ Google прямо сейчас |
| POST /api/live/gemini/key | Сохранение ключа после проверки |
| GET, POST /api/live/gemini/session | Состояние сессии и выпуск эфемерного токена |
| POST /api/live/gemini/session/stop | Завершение сессии |
| POST /api/live/gemini/tools | Исполнение вызовов инструментов, ответ для `toolResponse` |
| POST /api/live/gemini/frames | Зеркалирование кадров в лог, пачками |

## Что проверено

Живой разговор с телефона: распознавание, вызовы инструментов, изменение дерева,
транскрипт в логе, тосты с распознанным текстом. Повторное создание одних и тех же
задач при медленном ответе воспроизведено и закрыто защитой от повтора.

Не проверено автоматическим тестом: аудио-тракт в браузере (проверяется только с
устройства с микрофоном) и поведение при разрыве сокета посреди вызова.
