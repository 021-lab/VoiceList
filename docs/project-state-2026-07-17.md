# Project State — 2026-07-17

## Назначение

Репозиторий приведён к роли универсального интерфейса для форков: это не доменно-специфичный `SearchMyData`, а готовая база для touch-first списка задач с древовидной структурой.

## Текущее состояние

- основной deployable артефакт: `list-manager.html`;
- исходники живут в `src/`, а preview HTML собирается из `list-manager.template.html`;
- CI на GitHub запускает `prepare-preview`, проверяет exact `htmlpreview` URL от `GITHUB_SHA` и гоняет Playwright по задеплоенному preview;
- unit-тесты покрывают store, renderer, interpreter, sync, frontier и backend adapter;
- e2e-тест проверяет создание задачи, создание подзадачи, смену статуса и рендер на preview.

## Поведение интерфейса

- дерево задач хранится как плоский snapshot со связями `parentId`;
- поддерживаются статусы `Open`, `Done`, `Focus`, `Archive`, `Pause`;
- есть три пользовательских режима: основной список, фронтир и журнал действий;
- фронтир считает наиболее конкретные доступные задачи, включая фокус внутри `pause` и внутри закрытых предков, если к нему есть разрешённый путь;
- во вкладке фронтира каждая задача рендерится на полную ширину, а тап по ней циклически показывает и скрывает её родителя;
- жесты свайпа и drag остаются текущим контрактом интерфейса.

## Для форков

- меняйте seed snapshot в `list-data.js`;
- меняйте интерпретацию команд в `src/list-interpreter.js`;
- меняйте рендер и жесты в `src/list-renderer.js` и `src/list-ui.js`;
- не привязывайте CI и preview к конкретному владельцу репозитория: путь должен собираться от текущего `origin` или `GITHUB_REPOSITORY`.
