# Взаимодействие приложения v0.2

Один существующий по роли ListDocumentDO: DocumentRuntime координирует InteractionJournal, TaskGraph, ActionService, Presentation и AgentHarness с TaskAgent. На Dev используется отдельный namespace, не рабочий экземпляр Production.

## Информационные объекты
Реплика — готовый текст и контекст элемента интерфейса.
Команда — намерение агента или явное действие кнопки/перетаскивания через API.
Результат — факт исполнения или ошибки, связанный с причиной и командой.
Коррекция — новая реплика в контексте действия и связанные новые команды/результаты.
Граф задач — сохраняемый снимок проекции выполненных команд.
Документ интерфейса — дерево компонентов с ID, вычисленное Presentation из графа, видимого журнала и контекста экрана.

## Источник правды
Журнал — асинхронная шина и источник правды о взаимодействиях. Принятие реплики, решение и исполнение — отдельные этапы.
Полное восстановление графа по журналу не гарантируется; снимок графа необходим для работы.
Очередь SDK запускает обработку; она не заменяет журнал.
Необработанные записи остаются обнаружимыми после перезапуска, повтор не выполняет мутацию дважды.

## Поток
Client → Runtime → журнал реплики → Harness → TaskAgent → журнал ответа/команды → ActionService.
ActionService вызывает TaskGraph для изменения задач и записывает результат в журнал.
Runtime читает граф/журнал/контекст → Presentation.compose → дерево компонентов → Client.render.
Уточняющий ответ без команды не проходит через ActionService.
Расписание добавляет триггер журнала и использует тот же путь.
TaskGraph и Presentation напрямую в журнал не пишут.

## Изменения интерфейса
Команды API могут менять граф либо определять экран/выделение/уведомление конкретной сессии.
Отдельного универсального контейнера изменений нет: команда и связанный фактический результат достаточны.
Обычная локальная отрисовка, прокрутка и подсветка не создают журнальное действие.
Клиент не принимает произвольный JS/HTML модели; только разрешённые компоненты и действия.
