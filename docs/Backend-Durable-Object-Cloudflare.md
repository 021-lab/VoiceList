# Backend: единый Durable Object в Cloudflare

Документ описывает backend: он является источником истины для дерева задач и
обслуживает обычный интерфейс, а также обе голосовые кнопки.

## Архитектура

Все запросы к документу используют один экземпляр ListDocumentDO с постоянным
именем из переменной DOCUMENT_NAME. Имя и подсказка региона задаются в конфиге
воркера: объект создаётся один раз и остаётся в том регионе, где создан, поэтому
переезд — это копирование в объект с другим именем (POST /api/v2/relocate), а не
смена подсказки. Дев-документ живёт в main-apac, в Сингапуре.

    Browser UI
      -> WebSocket /ws
      -> Cloudflare Worker
      -> LIST_DOCUMENT.getByName(DOCUMENT_NAME)
      -> ListDocumentDO
      -> Durable Object Storage

В Durable Object хранится снимок списка, журнал действий и информация,
необходимая для повторной доставки команд. Все подключённые вкладки получают
новый полный снимок после каждого применённого изменения.

Голосовая сессия идёт отдельным путём. Их два, по кнопке на каждый.

GPT-Live:

    Browser
      -> POST /api/live/session (SDP)
      -> Worker -> Durable Object
      -> POST /v1/live/sessions (конфиг сессии + SDP)
      -> SDP answer -> Browser устанавливает WebRTC с моделью
      -> Durable Object открывает sideband WebSocket к той же сессии

Sideband получает те же события, что и браузер: через него ведётся лог и
исполняются вызовы инструментов. Подробности — в
docs/GPT-Live-Responses-Integration.md.

Gemini Live:

    Browser
      -> POST /api/live/gemini/session
      -> Worker -> Durable Object -> эфемерный токен от Google
      -> Browser открывает WebSocket прямо к Gemini
      -> вызовы инструментов: POST /api/live/gemini/tools -> Durable Object
      -> кадры для лога: POST /api/live/gemini/frames

Здесь sideband-соединения нет: браузер ретранслирует вызовы инструментов на
сервер и возвращает модели то, что ответил Durable Object. Подробности — в
docs/Gemini-Live-Integration.md.

Worker не проксирует аудиопоток. Он создаёт сессию от имени приложения, передаёт
скрытый контекст задач и хранит серверные настройки.

## Дерево и WebSocket-команды

Элемент списка содержит стабильный id, parentId, порядок, статус, заголовок,
дополнительный текст, tags и состояние сворачивания. Статусы: Open, Focus,
Pause, Done, Archive и Info.

Браузер открывает WebSocket на /ws. После соединения Worker отправляет текущее
сообщение state. Клиент затем отправляет:

    {
      "type": "command",
      "clientKey": "stable-id-of-browser-tab",
      "seq": 17,
      "input": {
        "actId": "task-id-or-list",
        "actType": "task-or-list",
        "command": "addItem | addChild | editItem | setStatus | setParent | ...",
        "payload": {},
        "source": "ui-or-gpt-live"
      }
    }

Ответ содержит ack со статусом applied или rejected, после чего всем клиентам
рассылается новый state. Пара clientKey + seq делает повторную отправку
идемпотентной. CloudflareDocumentClient хранит не подтверждённые команды в
localStorage и повторяет их после переподключения.

Команды, созданные голосовым агентом, идут тем же путём команд с
source: gpt-live или gemini-live, смотря какой кнопкой начат разговор. Это важно: голосовой агент не изменяет снимок в браузере
напрямую и не использует отдельный HTTP write API. Разница с прежней схемой в
том, что вызов исполняет Durable Object, а не вкладка браузера.

## HTTP-маршруты

| Маршрут | Назначение |
| --- | --- |
| GET / и GET /index.html | HTML-приложение. |
| GET /health | Проверка Worker; возвращает ok. |
| GET /api/tasks/tree.json | Полное вложенное дерево из id, title, status и children. Это read-only API; голосовой UI не загружает через него дерево при старте. |
| GET /api/tasks/frontier.json | Текущий фронтир, отсортированный по дедлайну. Каждая запись содержит parentTitle, taskId, taskTitle, status и deadline. |
| GET /api/live/key/status | Состояние конфигурации OpenAI-ключа. |
| POST /api/live/key | Одноразовое сохранение OpenAI API key. |
| GET, PUT /api/live/settings | Промпты всех слоёв, бэкенд-модель и модель Gemini; пустое значение означает встроенное умолчание. |
| GET /api/live/settings/history | История правок промптов с прежним и новым текстом. |
| GET, POST /api/live/session | Состояние голосовой сессии GPT-Live и её создание по SDP-предложению. |
| POST /api/live/session/stop | Завершение сессии и освобождение sideband. |
| POST /api/live/simulate | Прогон одного делегирования или одного хода голосового слоя по написанному транскрипту; документ не меняется. |
| GET /api/live/input | Настоящий вход прошлого делегирования по идентификатору ответа. |
| GET /api/live/log, /api/live/log/sessions | Лог событий сессий; читается открыто. |
| POST /api/live/log/clear, /api/live/log/repair | Очистка лога и дочитывание потерянных контекстов делегирований. |
| GET /api/live/gemini/key/status, POST /api/live/gemini/key | Ключ Gemini: проверяется у Google до сохранения и заменяем. |
| GET, POST /api/live/gemini/session, POST …/session/stop | Эфемерный токен сессии Gemini и её остановка. |
| POST /api/live/gemini/tools | Исполнение вызовов инструментов Gemini; браузер только ретранслирует результат. |
| POST /api/live/gemini/frames | Зеркалирование кадров сессии Gemini в лог. |
| GET /ws с Upgrade: websocket | Канал чтения и изменения документа. |
| GET /live-log, GET /bench | Страница лога голосовых сессий и стенд задержек. |
| GET /api/v2/where, /api/v2/bench, /api/v2/profile, POST /api/v2/relocate | Служебные: расстояние до объекта, замеры, профиль одной команды, перенос документа в другой объект. |
| POST /reset | Только тестовый сброс; требует TEST_RESET_TOKEN. |

Маршруты ключа, промпта и сессии отвечают с Cache-Control: no-store. Для
создания сессии и настройки ключа Worker проверяет Origin, если он передан.

## Конфигурация голосовой сессии

Браузер отправляет на /api/live/session только SDP. Дерево задач собирает
Durable Object и кладёт в инструкции голосового слоя плоской таблицей
id, parent, статус, название. Модель не должна озвучивать дерево без просьбы.

Используется gpt-live-1 с аудиовыходом marin и делегированием типа responses:
бэкенд-модель задаётся в настройках, инструменты объявлены в
delegation.responses.tools. Набор определён в src/v2/domain/live-session.js.

Read-only tool getFrontier используется для запросов «фронтир» и «что во
фронтире». Исполняет его, как и все остальные инструменты, Durable Object;
документ при этом не меняется. Браузер в исполнении инструментов не участвует ни
в одном из голосовых путей.

Сохранённый в настройках промпт заменяет встроенный целиком — правила о точных id,
неоднозначности и подтверждении результата живут именно в нём, и неудачная правка
их снимает. Система приписывает к промпту только то, что редактированию не
подлежит: блок `<capabilities>` перед ним (у GPT-Live, у которого своих
инструментов нет) и снимок задач `<tasks>` после него. Возврат к умолчанию —
очистка поля.

## Ключ и промпт

OPENAI_API_KEY из окружения Worker имеет приоритет. Если он не задан, ключ
можно единожды сохранить в Durable Object из страницы «Настройки». Браузер не
сохраняет ключ в localStorage; после успешного сохранения поле ключа блокируется.
Однократность здесь означает и то, что ошибочно сохранённый ключ не заменить из
приложения.

Ключ Gemini устроен иначе: он проверяется у Google до сохранения, и ключ, который
перестал приниматься, заменяется. GEMINI_API_KEY из окружения так же имеет
приоритет над сохранённым.

Промпты (голосового слоя GPT-Live, бэкенд-модели и Gemini), бэкенд-модель и модель
Gemini хранятся в том же Durable Object. Пустое значение означает встроенное
умолчание. Все настройки общие для документа, а не персональные для отдельного
браузера.

## Эксплуатационные ограничения

- Снимок задач кладётся в инструкции при старте сессии. В пути GPT-Live он
  догоняется дельтами через session.instructions.append; в пути Gemini дельт нет,
  и задача, созданная посреди разговора, видна модели только через getFrontier.
- Размер снимка ничем не ограничен, кроме состава статусов: Done и Archive в него
  не входят. Снимок участвует в каждом ходу голосового слоя, поэтому его размер —
  параметр стоимости.
- Один Durable Object означает единый общий документ. Разделение задач по
  пользователям или рабочим пространствам не реализовано.
- Разговоры с голосовым агентом хранятся на сервере: события обеих сессий пишутся
  в таблицу live_events того же Durable Object и читаются на /live-log.

## Сборка

Worker отдаёт worker/generated-html.js, а не исходный list-manager.html.
После изменения фронтенда нужно обновлять generated asset штатной командой
build:v2. Дев разворачивается npm run deploy:cloudflare, прод — отдельный воркер
с версионным откатом, см. docs/Prod-Deploy.md.
