# Бадди — OpenAI live voice

Статус: черновик, не реализовано. Основа — ветка `Claude/live-button`.

> **Ждёт решения владельца.** Документ написан под `gpt-realtime-2.1`, а нужна модель уровня
> Sol. `gpt-6.1-sol` не поддерживает звук и эндпоинты Live/Realtime, поэтому схема будет
> пересмотрена: скорее всего GPT-Live (`gpt-live-1`) с делегированием в `gpt-6.1-sol` и MCP.
> Разделы ниже про модель и топологию устарели до этого решения.

Третья голосовая кнопка рядом с GPT-Live и Gemini Live. Повторяет живой разговор из
приложения ChatGPT. Пользователь говорит без удержания кнопки, может перебить модель
голосом, а модель отвечает голосом и сама работает со списком через MCP.

## Решения владельца (интервью 2026-10-21)

| Предмет | Решение |
| --- | --- |
| Голосовая модель | Одна модель speech-to-speech без делегирования. По умолчанию `gpt-realtime-2.1`, меняется в настройках. «Sol 6.1» в API не найден, поэтому взята актуальная realtime-модель OpenAI. |
| GPT-Live и Gemini | Остаются. Одновременно работает одна голосовая сессия, и запуск новой останавливает активную. |
| Инструменты | Удалённый MCP-сервер VoiceList (`/mcp`), который OpenAI вызывает сам (`type: "mcp"`). |
| Набор MCP | Выравнивается с общими инструментами голосовых моделей (решение от 2026-10-18 остаётся в силе). |
| Дерево в контексте | Компактный снимок на старте, затем дельты. |
| Правка промпта | Бадди правит свой промпт по просьбе пользователя и после подтверждения. Правка применяется в той же сессии, перезапуск не нужен. |
| Где виден диалог | Панель «Диалоги» и Журнал действий, с пометкой «Бадди». |

## Топология

```
браузер ──WebRTC: аудио + data channel──► OpenAI Realtime (gpt-realtime-2.1)
   │  POST /api/live/buddy/session              │   ▲            │ MCP (Streamable HTTP)
   └────────────► Worker ──► документ-DO ───────┘   │            ▼
                                 │  sideband WS ◄───┘     https://<host>/mcp
                                 │  wss://api.openai.com/v1/realtime?call_id=…   │
                                 └────────── те же мутации дерева ◄──────────────┘
```

1. Браузер создаёт SDP-предложение и отправляет его в `POST /api/live/buddy/session`.
2. DO собирает конфиг сессии (раздел «Состав сессии») и обменивает SDP через
   `POST /v1/realtime/calls` с ключом проекта. Ключ уже хранится на сервере для GPT-Live.
3. DO открывает sideband `wss://api.openai.com/v1/realtime?call_id=<id>`. Через sideband он
   - пишет события в журнал,
   - отправляет дельты дерева,
   - отправляет `session.update` после правки промпта.
4. Инструменты исполняет OpenAI: он вызывает наш `/mcp`. Вызов приходит в тот же DO, поэтому
   мутации, журнал и рассылка `changed` идут обычным путём.

Без sideband сессия не запускается. Причина та же, что у GPT-Live: без него нет журнала,
дельт и применения промпта.

## Состав сессии

`session` в `/v1/realtime/calls`:

- `model`: из настройки, по умолчанию `gpt-realtime-2.1`.
- `instructions`: собирается из трёх блоков:
  1. Промпт Бадди: свой ключ настроек `buddy`, редактируется, хранит историю версий.
  2. Инструкция по использованию MCP: встроенная, не редактируется. Описывает, какой
     инструмент когда вызывать, как работать с id из таблицы, что подтверждать перед
     удалением и правкой промпта.
  3. Снимок дерева: формат GPT-Live (плоская таблица `id parent st title`, статусы O/F/P/I,
     без Done и Archive). Используется `formatTaskSnapshot`.
- `tools`: одна запись
  `{ type: "mcp", server_label: "voicelist", server_url: "https://<host>/mcp", authorization: "<токен сессии>", require_approval: "never" }`.
- `audio`:
  - голос по умолчанию: настройка;
  - VAD: `semantic_vad` с перебиванием;
  - расшифровка входа включена, чтобы реплики пользователя попадали в «Диалоги» и Журнал.
- `reasoning`: глубина из настройки, по умолчанию не задаётся.

### Токен MCP

Сейчас `/mcp` открыт без авторизации, его защищает только `MCP_ALLOWED_HOSTS`. Для Бадди
DO выпускает на каждую сессию случайный токен, хранит его и отзывает при остановке сессии.

- Запрос `/mcp` с этим токеном помечается источником `buddy` и id сессии. Так журнал знает,
  что правку сделал Бадди.
- Запросы без токена работают как сейчас. Закрытие `/mcp` для внешних клиентов в эту работу
  не входит.

## Инструменты MCP после выравнивания

Общий набор голосовых моделей плюс то, что уже есть в MCP. Имена остаются `voicelist_*`.
Схемы и описания берутся из одного источника — того же, из которого строится `LIVE_TOOLS`,
чтобы у двух путей не было двух копий.

| Есть сейчас в MCP | Добавляется |
| --- | --- |
| get_task_tree, get_task_subgraph | set_deadline |
| add_root_task, add_child_task, add_task_note | get_frontier |
| set_status, rename_task, move_task | get_buddy_prompt |
| delete_task, undo | set_buddy_prompt (`mode`: append \| replace) |

`get_buddy_prompt` и `set_buddy_prompt` видны только запросам с токеном Бадди. Внешний
MCP-клиент промпт не правит.

## Обновление контекста

- **Дерево.** После каждой мутации документа, из любого источника, DO отправляет в sideband
  `session.update` с `instructions`, к которым дописан блок дельт. Язык дельт — GPT-Live:
  `+ … ~ … * … > … ^ … -`. Реализация берётся из `diffSnapshotRows` и `chunkDeltaLines`.
  Когда дельт накопится больше порога, снимок пересобирается целиком.
- **Промпт.** `set_buddy_prompt` сохраняет новую версию: старая уходит в историю, и её можно
  откатить в настройках. Затем DO отправляет `session.update` с пересобранными
  `instructions` (новый промпт, инструкция MCP, свежий снимок). Результат инструмента
  сообщает модели, что новый промпт уже действует.
- Правка промпта в настройках во время активной сессии применяется так же.

## Журнал и «Диалоги»

- **Реплики.** Финальные расшифровки пользователя и модели попадают в журнал взаимодействий
  (`kind: speech`, `source: 'buddy'`). Так это уже сделано у GPT-Live и Gemini. Реплика
  пишется одной записью, без фрагментов.
- **Вызовы инструментов.** Мутации через `/mcp` с токеном Бадди попадают в журнал как
  команды с `source: 'buddy'`. Там работают откат и комментарии, как у остальных записей.
  Читающие вызовы (дерево, фронтир, промпт) в Журнал не попадают, потому что Журнал
  показывает действия.
- **Правка промпта** — отдельная запись журнала: «Бадди изменил свой промпт» с текстом
  правки.
- **Панель «Диалоги»** показывает реплики по мере речи. Источник — data channel, как у
  GPT-Live. Вызовы инструментов показываются строками между репликами: имя, аргументы,
  успех или ошибка. Берутся из событий `response.mcp_call.*` и
  `conversation.item.done` (`mcp_call`).
- **Технический лог.** Сырые события sideband пишутся в `vl_live_events` с id сессии Бадди,
  поэтому `/live-log` их видит. На странице лога это отдельная фильтрация не требует.
- В Журнале пометка источника — «Бадди», как сейчас «GPT-Live» и «Gemini»
  (`client.js`, словарь `origin`).

## Клиент

- Новая кнопка `buddy-voice-btn` рядом с двумя существующими, с тем же набором состояний:
  `idle → connecting → live → error`.
- Новый модуль `src/v2/client/buddy-voice.js`. Он повторяет WebRTC-часть
  `live-voice.js`: микрофон, peer connection, data channel, обработка событий.
  Отличаются адрес сессии и имена событий Realtime API.
- Вторая кнопка во время сессии или кнопка остановки завершает сессию через
  `POST /api/live/buddy/session/stop`.
- Новый раздел настроек «Бадди»:
  - промпт (сохранить, вернуть встроенный, история);
  - модель;
  - голос;
  - глубина рассуждений.

## Сервер

- `worker/v2/buddy-host.js` — класс по образцу `LiveHost`. Он делает:
  - `start({ sdp })`;
  - `attach(callId)`;
  - `receive`: журнал, реплики, mcp-события;
  - `pushDelta(items)`;
  - `refreshInstructions()`;
  - `stop()`.
- `src/v2/domain/buddy-session.js` — чистые функции: конфиг сессии, сборка `instructions`,
  разбор событий. Покрываются юнит-тестами без сети.
- Новые маршруты в `worker/v2/index.js`: `/api/live/buddy/session`, `/api/live/buddy/session/stop`.
- `LiveSettings`: цель `buddy` в `PROMPT_TARGETS` и ключи для модели, голоса и глубины.
- `worker/v2/mcp.js`:
  - инструменты строятся из общего источника;
  - проверяется токен Бадди;
  - команды с токеном Бадди получают `source: 'buddy'`.
- Взаимоисключение: старт Бадди останавливает GPT-Live и Gemini, а их старт останавливает
  Бадди (`document-do.js`, по образцу строки с `replaced-by-gpt-live`).

## Нагрузка на Durable Object

Каждый MCP-вызов — это запрос к DO, и OpenAI делает `tools/list` в начале сессии. Дельты
идут через уже открытый sideband, новых запросов к DO не добавляют. Кадры в DO не
зеркалируются, в отличие от Gemini.

## Проверка готовности

1. Юнит-тесты `buddy-session.js`:
   - конфиг содержит MCP-инструмент с токеном;
   - `instructions` = промпт + инструкция MCP + снимок;
   - дельта после мутации;
   - пересборка после правки промпта.
2. Юнит-тест `mcp.js`:
   - полный набор инструментов;
   - `set_buddy_prompt` отказывает без токена;
   - команда с токеном получает `source: 'buddy'`.
3. Интеграционный тест worker с подменённым OpenAI. Сценарий:
   - старт;
   - sideband получает `session.update` с дельтой после мутации;
   - `stop` отзывает токен.
4. Живая проверка на проде голосом:
   - «добавь задачу X во входящие» — задача появилась, в Журнале запись «Бадди», в «Диалогах»
     реплики и строка вызова;
   - «запомни: отвечай короче» — после подтверждения промпт изменён в настройках, и
     следующий ответ уже короче, без перезапуска;
   - перебивание голосом обрывает ответ модели.

## Порядок работ (каждый пункт — отдельный коммит и выкат)

1. MCP получает общий набор инструментов (set_deadline, get_frontier).
2. Промпт Бадди в настройках: цель `buddy`, раздел настроек, история.
3. Кнопка Бадди: сессия, sideband, MCP с токеном, реплики в «Диалогах» и Журнале.
4. Дельты дерева в активную сессию.
5. Правка промпта голосом с применением в той же сессии.

## Открытые вопросы

- Голос по умолчанию: предлагаю `marin`.
- Ограничение длины сессии и расхода: Realtime тарифицируется по аудио. Предлагаю
  автоостановку после 2 минут тишины.
