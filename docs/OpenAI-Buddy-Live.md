# Живой голос GPT-Live с бэкендом Sol

Статус: шаги 1–2 на проде (версии #33, #34), шаг 3 ждёт решения владельца.
Отменяет черновик отдельной кнопки «Бадди» на `gpt-realtime-2.1`.

## Почему так

`gpt-6.1-sol` — текстовая модель: звука нет, Live и Realtime недоступны, работает только
через Responses. Поэтому разговором управляет `gpt-live-1` (дуплекс, перебивания, паузы, как
в приложении ChatGPT), а думает и вызывает инструменты Sol через делегирование
`responses`. Кнопка — существующая GPT-Live.

## Что сделано

1. **Бэкенд по умолчанию — `gpt-6.1-sol`** (#33). Сохранённая в настройках модель
   важнее умолчания: на проде сохранена `gpt-5.6-sol`, её нужно очистить в настройках.
   Рассуждения: Sol поддерживает `low`…`max`, для отзывчивости — `low`; `none` Sol
   отклонит.
2. **Новые промпты и таблица у бэкенда** (#34).
   - Голос отвечает сразу одной-двумя фразами, при перебивании замолкает, вслух называет
     действие и задачу по названию («Ставлю Клубнику на паузу») — эта фраза и есть
     команда. Идентификаторы не произносит. По своей таблице сам отвечает на вопросы о
     состоянии и сам уточняет, если названию подходят несколько задач.
   - Бэкенд получает в инструкциях свою таблицу задач (`composeBackendInstructions`) и
     строку «Сегодня YYYY-MM-DD». По названию из расшифровки находит id; при
     неоднозначности ничего не меняет и возвращает вопрос; новая задача без места — во
     «Входящие».
   - После каждого изменения DO отправляет `session.update` с пересобранными
     инструкциями бэкенда до `response.create`, а голосу — дельты, как раньше. Правка
     промпта бэкенда моделью применяется так же, в той же сессии.

Проверка промпта бэкенда на `gpt-6.1-sol`, `low`, шесть фраз без идентификаторов: все
шесть верно (статус, уточнение «Клубнику в Хлебе или на Даче?», выбор по родителю,
«Входящие», перенос, дедлайн «на завтра»), 1,7–2,9 с до вызова инструмента.

## Шаг 3: MCP вместо функций — открыт

Делегирование принимает `{ type: "mcp", server_url: ".../mcp" }` (сессия создаётся, 201), и
Sol через Responses вызывает наш `/mcp` (`mcp_list_tools` → `mcp_call`). Но MCP медленнее:
чтение дерева с ответом — около 6 с против одного прохода с функцией через sideband, где
DO уже держит соединение. Каждый MCP-вызов — ещё и отдельный HTTP-запрос к DO.

Если MCP всё же нужен, план: выровнять набор `/mcp` с `LIVE_TOOLS` (set_deadline,
get_frontier, правка промптов) из одного источника схем; токен сессии в `authorization`,
чтобы журнал помечал источник `gpt-live` и чужой клиент не правил промпты; синхронизация
таблиц после мутаций уже срабатывает на любое изменение документа.

## Известные ограничения

- «Сегодня» считается в UTC, как у текстового агента: с 00:00 до 03:00 по Москве «завтра»
  будет на день раньше.
- Голосовой слой (`gpt-live-1`) через Responses не воспроизвести, его промпт проверяется
  только живым разговором.
