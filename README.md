# VoiceList

`VoiceList` теперь оформлен как универсальная база для форков: одностраничный HTML-интерфейс для иерархических списков задач с touch-first UX, htmlpreview-деплоем и CI-проверкой готового превью.

## Что внутри

- вложенный список задач с drag, swipe и fullscreen-редактированием;
- статусы `Open`, `Done`, `Focus`, `Archive`, `Pause`;
- отдельные вкладки списка, фронтира и журнала действий;
- единый контракт ввода через интерпретатор команд;
- self-contained `list-manager.html` для деплоя через GitHub + `htmlpreview`.

## Как использовать как базу для форка

1. Форкните репозиторий.
2. Меняйте `list-data.js` под свой seed snapshot.
3. Переопределяйте тексты, цвета и интеграции в `src/` и шаблоне `list-manager.template.html`.
4. Генерируйте deployable HTML через `npm run prepare-preview`.
5. Пушьте изменения: CI сам проверит exact `htmlpreview` URL от коммита.

## Голосовое управление

Кнопка микрофона (правый нижний угол) запускает распознавание через Web Speech API
(`ru-RU`). Распознанная фраза разбирается в `src/list-voice.js` и уходит в тот же
интерпретатор команд, что и тач-ввод, поэтому каждое голосовое действие попадает
в журнал и поддерживает undo.

| Фраза | Команда |
| --- | --- |
| «добавь задачу купить молоко» | `addItem` |
| «добавь задачу кофе с подписью арабика 250 грамм» | `addItem` + вторая строка |
| «добавь подзадачу голден к яблоки» | `addChild` |
| «переименуй кофе в чай» | `editItem` |
| «удали шампунь» | `deleteItem` |
| «отметь хлеб выполнено» | `setStatus` → `Done` |
| «фокус на кофе» | `setStatus` → `Focus` |
| «в архив шампунь», «поставь молоко на паузу», «верни шампунь» | `setStatus` |
| «пометь молоко как срочно» | `setTags` |
| «сверни яблоки» | `toggleCollapse` |
| «покажи список» / «покажи фронтир» / «покажи журнал» | переключение вкладок |
| «отмена» | `undo` последнего голосового изменения |

Название задачи ищется нечётко (нормализация регистра, `ё`, пунктуации и лёгкий
стемминг), так что «яблоко» находит «Яблоки». Если фраза не распознана или задача
не найдена, состояние не меняется — в строке статуса появляется причина.

Поддержка браузера определяется на старте: без `SpeechRecognition` кнопка
блокируется, остальной интерфейс работает как раньше.

## Деплой на Railway

```bash
railway up            # или подключите репозиторий к сервису Railway
```

`railway.json` описывает сборку (`npm ci && npm run build`) и старт
(`npm start`). Сервер `scripts/static-server.mjs` слушает `PORT`/`HOST` из
окружения (`0.0.0.0`, если `PORT` задан) и отвечает `ok` на `/health` —
этот путь используется как healthcheck.

Проверить ровно ту же конфигурацию локально:

```bash
npm ci && npm run build
PORT=4610 npm start
PLAYWRIGHT_BASE_URL="http://127.0.0.1:4610/list-manager.html" npm run test:e2e
```

## Локальная разработка

```bash
npm ci
npm run test:unit
npm run prepare-preview
npm run test:e2e
```

## Preview

Финальный preview для каждой версии строится от точного `commit SHA`, а не от имени ветки. Это уменьшает проблемы с кэшем и делает CI-результат воспроизводимым.
